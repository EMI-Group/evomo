# 约束多目标优化

## 违反量约定

`CMOP.evaluate(population)` 返回 `(fitness, cv)`：目标形状为 `(N, M)`，
违反量形状为 `(N, n_iq + n_eq)`，每列对应一个约束。

- 不等式按 `g(x) <= 0` 定义，违反量为 `max(g(x), 0)`。
- 等式违反量为 `max(abs(h(x)) - constr_eq_eps, 0)`，默认容差为 `1e-4`。
- 所有违反量均为零时解可行；当前选择逻辑按总违反量进行比较。

原始负数不等式值表示满足约束，不应直接作为违反量使用。
当前 `CMOP.evaluate` 始终返回二元组；构造参数 `return_cv` 不改变这个返回约定。

NSGA-II 在初始化和每代选择中保留违反量。可行解优先于不可行解；不可行解之间优先比较
总违反量；可行解之间或总违反量相等时，再比较目标支配关系。

## 提取可行前沿

先按违反量和有限目标值筛选，再对剩余目标计算零等级前沿。
不要用仅按目标提取的前沿替代可行前沿，也不要只查看某个目标的最小值来判断是否成功。

当没有可行解时，应报告可行率或违反量统计；GD、IGD 需要非空的输入解集，
此时不能报告可行前沿的距离指标。

## 接入其他算法

`IBEA` 和 `HypE` 可以通过 `UnifiedWorkflow` 接收 `(fitness, cv)`，并保存选中个体的违反量。
这两个实现是在已有张量化算法上加入可行性优先规则；PlatEMO 的基础 IBEA、HypE 没有使用约束。
父代选择先比较总正违反量，再比较指标适应度或估计的超体积贡献，完全相同的比较键仍保持并列。
IBEA 优先删除违反量最大的个体，违反量相等时沿用逐次指标删除，并对约束运行中的常数目标范围
和零指标缩放增加保护。

HypE 先对可行解按目标支配关系分层，再对不可行解按违反量分层，相同违反量属于同一层。
完整层优先保留，截断层通过固定形状掩码计算超体积贡献并批量选择。无约束运行保留已有的批量
选择方式；该实现不等同于 PlatEMO 逐次重算贡献并删除个体的过程。

`RVEAa` 在前沿筛选、参考向量选择和最终截断中都保留违反量。分区选择参考 PlatEMO RVEAa：
优先选 APD 最小的可行解，没有可行解时选违反量最小者。约束运行的前置第一层筛选将总违反量
作为额外目标，与原目标联合比较支配关系。这是对 PlatEMO 仅按目标预筛选的扩展，既保护可行解，
也保留目标和违反量之间的权衡，避免过早退化为单个最小违反量个体。最终批量截断
优先比较违反量，再比较最近邻角度拥挤程度，最多保留采样种群数个有效槽位，其余槽位的种群、
目标和违反量均以 NaN 填充。这是角度截断的批量近似，不等同于 PlatEMO 的逐次截断过程。
无约束运行保留原来的筛选与截断逻辑。约束运行的自定义环境选择接收
`(pop, fit, vectors, theta, cv)` 并返回 `(pop, fit, cv)`，与 RVEA 的约束接口一致。

`TensorMOEAD` 可以通过 `UnifiedWorkflow` 接收 `(fitness, cv)`，并在 `cv` 中保存选中个体的
违反量。两轮更新都优先比较总正违反量：子代违反量更小时可以替换邻居；违反量相等时，要求第一
聚合值严格改善。多个子代竞争同一子问题时，第二轮先选违反量最小者，再比较第二聚合值。
该约束比较方式参考 PlatEMO C-MOEA/D，同时保留 TensorMOEA/D 的批量更新框架和严格改善规则。
理想点及目标范围仍由所有评价结果更新。约束比较使用固定形状张量操作；无约束运行保留原来的
仅按聚合值更新路径。

`NSGA3` 可以通过 `UnifiedWorkflow` 接收 `(fitness, cv)`，并在 `cv` 状态中保存选中个体的
违反量。约束运行参考 PlatEMO NSGA-III：父代锦标赛比较总正违反量；环境选择先对可行解按目标
支配关系分层，再对不可行解按违反量分层。总违反量相等的不可行解属于同一层，由参考点小生境
选择处理截断层。违反量通过固定形状张量排序处理，避免为每个不同违反量逐层处理。
`z_min` 保存历史可行理想点；尚无可行解时，归一化暂以全 1 为理想点，并保留已有的退化归一化
保护。无约束运行保持原来的按等级选父代和归一化方式。自定义父代选择接口仍是
`(pop_size, keys)`：无约束时传入等级，约束时传入总正违反量。

`RVEA` 也可以通过 `UnifiedWorkflow` 接收 `(fitness, cv)`，并在 `cv` 状态中保存与种群、
目标值逐行对应的违反量。空参考向量槽位的三个张量均用 NaN 填充。选择遵循 PlatEMO RVEA：
每个参考向量分区内，有可行解时选 APD 最小的可行解；全部不可行时选总正违反量最小的解。
这是分区内的可行性优先规则，因此其他分区仍可保留不可行解。约束选择使用固定形状的张量掩码。
约束运行的自定义 `selection_op` 应接收 `(pop, fit, vectors, theta, cv)` 并返回 `(pop, fit, cv)`；
无约束运行仍使用原来的四参数、双返回值接口。

## 其余算法的约束支持

目前公开导出的 57 个算法类均可接收纯目标张量或 `(fitness, cv)`。本次补齐的 50 个类如下。
无约束评估不进入约束比较路径；下述独立搜索与批量更新修复可能改变无约束轨迹。
约束状态随同一个索引更新，保证与决策变量、目标、掩码、个人最优
和各自的档案对应。新接入的算法在张量设备上累加正违反量，负不等式值先截断为零。
保存的 `cv` 仍是问题返回的原始值。对二维违反量，应使用 `cv.clamp_min(0).sum(dim=1) == 0`
判断可行性，并排除非有限目标值；对一维总违反量使用 `cv.clamp_min(0) == 0`。
同一个问题的评估返回结构应始终一致。

| 类别 | 新增支持的算法 | 约束处理 |
| --- | --- | --- |
| 支配与前沿选择 | `AGEMOEA`、`BiGE`、`GDE3`、`GrEA`、`KnEA`、`NSGAII_SDR`、`OSP_NSDE`、`SIBEA`、`SNSGA2`、`VaEA` | 约束支配或约束分层，再使用原有拥挤度、几何、网格或指标规则。同正违反量的不可行解共享一层。 |
| 稀疏决策 | `DMMOEA`、`SparseEA`、`SparseEA2`、`TSSparseEA` | 变量探测使用目标与总违反量的联合前沿；环境选择使用约束前沿；掩码与违反量同步保留。 |
| 分解 | `MOEAD`、`MOEADAWA`、`MOEAD_DCWV`、`MOEADDE`、`MOEAD_DRA`、`MOEADDU`、`MOEADDYTS`、`MOEADFRRMAB`、`MOEAD_PaS`、`MOEAURAW`、`BCEMOEAD` | 参考 C-MOEA/D：先比较总违反量，相等时比较原有聚合值；保留邻域和替换数量限制。约束批量更新通过归约解决同一位置的多个替换提议。 |
| 指标与档案 | `BCE_IBEA`、`Two_Arch2`、`SSCEA`、`PICEAg`、`PREA`、`eMOEA`、`PESA2` | 种群与档案选择加入约束，原有指标、目标向量、epsilon 网格或多样性处理平局。每个档案保存独立违反量。 |
| 参考向量与标量选择 | `CLIA`、`ThetaDEA`、`tDEA_CPBI`、`SPEAR`、`MaOEACSS`、`WASFGA`、`GWASFGA` | 违反量优先与原有聚类、参考向量或标量选择结合。 |
| 粒子群 | `CMOPSO`、`SMPSO`、`LMOCSO`、`TELSO` | 违反量进入竞争、个人最优和档案更新。LMOCSO/TELSO 在参考分区内优先可行 APD 解，否则选择最小违反量，允许其他分区保留不可行解。 |
| 其他结构 | `CMOEA_MS`、`CoMMEA`、`NSBiDiCo`、`EFRRR`、`LSMOF`、`TSNSGAII`、`WOF` | 违反量贯穿双种群、辅助档案、阶段选择、方向/权重探测或变换后的决策评估。 |

`CMOEA_MS` 参考 PlatEMO 的两个评分阶段：早期共同优化移位密度与归一化违反量；当可行比例
大于 `lambda_`，且达到 `max_gen` 的 10% 后，使用目标与约束的强度适应度。
每一列约束单独归一化，再取平均。新增可选参数默认 `max_gen=100`、`lambda_=0.5`；
`max_gen` 仅控制阶段切换，终止条件仍由调用方决定。早期阶段可以保留目标与约束之间的折中解。
约束 `CoMMEA` 保持第二种群的数量：先比较违反量，再比较 epsilon 筛选资格和双空间拥挤度；
筛选仅剩单个候选时从完整候选池补足，避免后续密度计算越界。
`NSBiDiCo` 辅助档案也使用目标/违反量联合前沿，主种群使用约束前沿；其档案允许保留可行解，
没有逐字移植 PlatEMO 的仅不可行解档案和双向父代选择。

参考实现为 [PlatEMO](https://github.com/BIMK/PlatEMO/tree/d25e65d1ffba58dbf4d7e1b5259786187d12968a/PlatEMO/Algorithms/Multi-objective%20optimization)，
主要采用约束 NDSort、C-MOEA/D、CMOEA-MS 与参考分区选择规则。
PlatEMO 中不少基础算法只比较目标，例如多数 MOEA/D 变体、指标、网格和粒子群算法；这里为其
扩展了约束比较。原有 EvoMO 近似实现仍然保留，不能当作所有 PlatEMO 算子、归一化、档案和
截断规则的精确复现。具体而言，`tDEA_CPBI` 在现有聚类选择中增加违反量优先，没有移植
PlatEMO 完整的约束归一化流程。稀疏变量探测将多列约束合为总违反量后联合排序，PlatEMO 则
使用各约束列。对常数目标及零归一化跨度做了保护。

约束 `PESA2` 按前沿补足请求的种群数量，仅在截断前沿内做网格删除，避免全不可行时
只保留最小违反量前沿而缩成单个个体。约束 `eMOEA` 从被支配成员中随机选取替换位置，
减少批量后代集中覆盖同一位置。约束 `DMMOEA` 增加实数多项式变异，重复候选不足时
补足种群，避免前沿选择无法结束。约束 `MOEAD_DRA` 也使用多项式变异。
`MOEAD_DRA`、`MOEADAWA`、`MOEADDYTS`、`MOEADFRRMAB` 的资源分配优先奖励
违反量的相对改善，违反量相同时奖励目标改善，约束模式的效用限制在 [0, 1]。
约束 `OSP_NSDE` 在达到可行性之前保留常规变异，之后周期性使用现有近似预测，
没有完整移植 PlatEMO 的 ARX/HV 触发流程。

`SMPSO` 仅从已占用档案位置选择领袖；变异先以 0.15 的概率选择粒子，算子内部的
1/D 变量概率只使用一次。这两项修复也作用于无约束运行，因此搜索轨迹可能变化。
评价其质量时应同时检查可行档案与当前粒子群。NaN 违反量按正无穷比较，原始值仍保留。

EvoX 多项式变异的 `pro_m` 表示每个个体的期望变异变量数，算子内部会除以 D。
`BiGE`、`CMOPSO`、`KnEA`、`MaOEACSS`、`CMOEA_MS`、`NSGAII_SDR`、`EFRRR`、
`TSNSGAII`、`TSSparseEA`、`WOF` 使用 `pro_m=1` 实现 1/D 的变量概率，修复了原先的
1/D² 概率。`eMOEA`、`MOEADAWA`、`PREA` 按 SBX 的前后半批规则排列配对父代，
PREA 每代产生 N 个后代，与 PlatEMO 的 `OperatorGAhalf` 一致，比较时应对齐评价次数。
无约束 `eMOEA`、`MOEADDE`、`MOEAD_DCWV`、
`MOEADFRRMAB` 对重复替换位置归约选定同一个最后来源，同时更新决策与目标，避免分开
进行 CUDA 冲突写入时两个张量选中了不同后代。这些修复同时作用于适用的约束和无约束路径。

后续源码核查修正了 PREA 比值指标的支配方向，并在每次多样性删除后重新计算指标最小值。
CMOPSO 在每个前沿内计算领袖拥挤度，选择两个不同领袖，角度相等时保留第一个，并使用逐次距离截断。
CMOEA-MS 的无约束与约束运行采用相同两阶段评分：早期移位密度使用归一化欧氏距离，
后期强度适应度及截断使用原始目标的余弦距离。KnEA 使用互不重复的最大目标极值点和
带符号的超平面距离，并根据上一轮膝点比例调整半径；极值矩阵奇异时用伪逆保护。

MOEADAWA 增加 `max_evaluations` 控制调整时机，包含初始化评价。应设为实际运行预算；
默认值是 `100 * 实际种群数`，它不控制终止。效用每十个种群等价评价周期更新；档案和
权重调整从 `rate_evol=0.8` 开始。默认 `weight_update_interval=100` 按原算法的五个
子代周期折算。父代池采用无放回随机排列，替换候选也来自同一个池。权重调整使用逐次
近邻距离乘积截断，并保留未删除子问题的权重。每个子代周期内仍批量产生后代，PlatEMO
则逐个产生；权重改变后这里刷新邻域，参考主循环仍保留最初的邻域矩阵。

部分既有近似仍会影响与原算法的比较：eMOEA 批量更新 epsilon 档案，MOEADDYTS 简化了
五种变异算子和逐子代 bandit 更新，MOEADFRRMAB 批量分配算子奖励，TSSparseEA 近似
实现原版的分组二进制优化。约束比较通过测试不等于完整搜索过程与 PlatEMO 等价。

约束比较使用批量张量运算，适用处采用固定形状归约。但一些完整算法原有的数据相关循环、
动态档案或布尔索引仍然限制 `torch.compile(fullgraph=True)`，约束支持并不意味着整个算法
都支持完整图编译、CUDA graph 或 `vmap`。测试环境为 Windows/PyTorch 2.11：EFRRR 可捕获
完整图，但 CPU Inductor 会破坏目标张量类型，原版无约束 EFRRR 也可复现；CUDA Inductor
与 CPU AOT eager 检查通过。编译前应先初始化工作流。
`MOEAD` 和 `LMOCSO` 有显式 `device` 构造参数，使用 CUDA 边界时应同时传入。

约束运行仍要求：问题返回违反量，工作流保留元组（例如 `UnifiedWorkflow`），算法消费违反量。
GD/IGD 只在有限的可行解上计算；没有可行解时报告可行率与违反量，GD/IGD 记为不可用。
比较随机算法质量时使用多个种子与相同评估预算；变量探测和参考点采样会使相同代数的评估成本不同。
