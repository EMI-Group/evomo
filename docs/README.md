# Documentation maintenance and local builds

The documentation uses Sphinx, MyST Markdown, and the Shibuya theme. English is the primary
language, with complete Chinese guides under `zh_CN/`. API signatures and source docstrings
are generated by Sphinx AutoAPI through static source parsing. Building does not require
EvoMO, PyTorch, CUDA, Brax, or JAX.

Run from the repository root:

```sh
python -m pip install -r docs/requirements.txt
python -m sphinx -b html -W --keep-going docs docs/_build/html
```

Open `docs/_build/html/index.html`, or start a local server:

```sh
python -m http.server 8000 --directory docs/_build/html
```

Visit <http://localhost:8000> for English and <http://localhost:8000/zh_CN/index.html> for Chinese.
The generated output under `docs/_build/` is ignored by Git.

## File layout

- `index.md`, `guide/`, `development.md`, and `reference/index.md`: primary English documentation.
- `zh_CN/`: matching Chinese home, guides, development notes, API overview, and backend guide.
- `examples/`: shared Python scripts included by both languages.
- `_templates/page.html`, `_static/languages.css`: language switch and its styling.
- `conf.py`, `requirements.txt`: build configuration and separate documentation dependencies.
- `non_dominate_backends.md`: the existing English source of backend requirements and limitations.
- `reference/parameters.md` and its Chinese counterpart: parameter conventions, special settings, and operator contracts.
- `reference/citation.md` and its Chinese counterpart: the README's EvoMO and related algorithm papers.
- `_static/evomo.bib`: shared, downloadable BibTeX entries used by both citation pages.
- `images/evox_brand_*.svg`: the existing EvoX family logos, reused by the light and dark document headers.
- `_static/branding.css`: keeps the EvoMO name beside the shared family logo.

## Writing API docstrings

Keep constructor documentation in `src/evomo/algorithms/` so AutoAPI, IDE help, and Python's
`help()` use the same explanation. All public algorithm constructors document every named
parameter, plus `**kwargs` where accepted. Use Sphinx `:param name:` and `:type name:` fields.
Explain required inputs, tensor shapes, default values (including the meaning of `None`),
device handling, valid ranges, and the parameter's effect. Document accepted but unused
arguments explicitly; do not infer behavior from an algorithm's name.

Generated algorithm pages omit instance attributes without docstrings, which otherwise
repeat constructor fields or expose unexplained internal state. Attributes with their own
documentation remain visible. To add a public state entry, document that attribute in source.

Distinguish schedules from termination, mating selection from environmental selection, and
workflow steps from objective evaluations. Keep the English and Chinese parameter guides
consistent when changing defaults or behavior. For documentation-only source edits, verify
that executable code is unchanged and run the strict Sphinx build above.

## Keeping languages consistent

For each English guide, use the same relative filename under `zh_CN/`. The language switch
opens the corresponding chapter. HTML language tags identify English and Chinese pages.
The sidebar renders only the selected language's homepage toctrees. Keep the hidden Chinese
homepage entry in the English root for document discovery; it is excluded from the visible
English sidebar. Brand, breadcrumbs, and previous/next links stay within the selected language.
Generated API pages are shared in English, and their switch links to the two guide homepages.
Chinese pages localize the page-outline and previous/next labels. Search and other common
theme controls use English, the site's default UI language.

Add new chapters to both homepages' `toctree` directives. Update both versions when changing
interfaces, formulas, limits, or examples. Use `literalinclude` to reference shared scripts:
English guides use `../examples/`, and Chinese guides use `../../examples/`.
The Chinese API overview links to the shared generated pages; keep the API toctree in the
English overview to avoid duplicating the navigation hierarchy.

Do not commit generated `autoapi/` or `_build/` contents. The root `.readthedocs.yaml` supplies
a hosting configuration. A maintainer must connect the repository in Read the Docs to publish;
adding the file does not create a hosted documentation site.

## Reference sources

The information architecture follows [EvoX documentation](https://evox.readthedocs.io/en/latest/index.html),
and Markdown and code documentation organization follows its
[Document Writing Guide](https://evox.readthedocs.io/en/latest/guide/developer/document.html).
EvoMO interfaces, defaults, and behavior are checked against this repository's source.

## 中文维护说明

英文是主文档，中文完整章节位于 `docs/zh_CN/`，路径与英文逐章对应。
修改接口、公式、限制或示例时同步更新两种语言。两版共用 `docs/examples/` 中的脚本和英文 API 页。
构建命令与上文相同；英文入口为 `index.html`，中文入口为 `zh_CN/index.html`，
页面上方的语言链接可切换到对应章节，左侧目录只显示所选语言，并保持首页和前后页导航的语言一致。
中文页的本页目录与前后页标签使用中文；搜索和其他通用主题控件默认使用英文。
